# OSC インターフェース

**OSC (Open Sound Control)** インターフェースを使用すると、OSCプロトコルを介してネットワーク経由でDMX照明データを送受信できます。

## 入力（レシーバー）

**入力**として設定すると、アプリケーションはDMXデータを含むOSCメッセージをリッスンします。

### 設定

| 設定                | 説明                                                                                                                                 |
| :------------------ | :----------------------------------------------------------------------------------------------------------------------------------- |
| **ホスト**          | リッスンするネットワークアダプター（IPアドレス）。すべてのインターフェースでリッスンする場合は `0.0.0.0` を使用します。                 |
| **ポート**          | リッスンするネットワークポート。デフォルトは `8000` です。                                                                            |
| **OSC パス**        | マッチするOSCアドレスパターン。チャンネル番号のプレースホルダーとして `:channel` を使用します。例：`/dmx/:channel` または `/0/dmx/:channel`。 |
| **開始チャンネル**  | 受信する最初のDMXチャンネル（1-512）。                                                                                                |
| **長さ**            | 受信する連続したDMXチャンネルの数（1-512）。                                                                                           |
| **データタイプ**    | データ形式：**Int**（0-255の整数）、**Float**（0.0-1.0の正規化された値）、または **Blob**（ユニバース全体のバイナリデータ）。          |

### 使用例

#### チャンネルごとモード

個々のチャンネルメッセージを受信するには、**OSC パス**を `/dmx/:channel` に設定します：
- `/dmx/1` に値 `255` を送信すると、チャンネル1が255に設定されます
- `/dmx/100` に値 `128` を送信すると、チャンネル100が128に設定されます

#### ユニバース全体モード

単一のメッセージですべてのチャンネルを受信するには、**OSC パス**を `/dmx/universe`（`:channel` プレースホルダーなし）に設定します：
- **Int** または **Float** の場合：メッセージ引数は連続したチャンネル値として解釈されます
- **Blob** の場合：バイナリデータにチャンネル値がバイトとして含まれます

## 出力（トランスミッター）

**出力**として設定すると、アプリケーションはOSCメッセージを介してDMXデータを送信します。

### 設定

| 設定         | 説明                                                                                             |
| :----------- | :----------------------------------------------------------------------------------------------- |
| **ホスト**   | 宛先IPアドレス。ローカルホストの場合は `127.0.0.1`、リモートターゲットの場合は特定のIPを使用します。  |
| **ポート**   | 宛先ネットワークポート。デフォルトは `8000` です。                                                 |
| **OSC パス** | データを送信するOSCアドレス。例：`/dmx` または `/universe/0`。                                      |
| **FPS**      | フレームレート。OSCメッセージが送信される頻度を制御します。                                         |

**注意**: 出力は常に**DMXユニバース全体（512チャンネル）をバイナリブロブとして**送信し、最大の効率とシンプルさを実現します。

### 使用例

トランスミッターは、512個のDMXチャンネルすべてを単一のOSCメッセージでバイナリブロブとして送信します：
- OSCアドレス: `/dmx`（またはカスタムパス）
- データタイプ: ブロブ（512バイトを含むバイナリデータ）
- 各バイトは1つのDMXチャンネル値（0-255）を表します

## OSC プロトコルの詳細

ObakesanはUDP上の標準OSCプロトコルを実装しています：

- **トランスポート**: UDP over Ethernet/Wi-Fi
- **メッセージ形式**: タイプタグ付きOSCメッセージ
- **出力形式**: 512個のDMXチャンネル値を含むバイナリブロブ
- **入力サポート**: 整数（`i`）、浮動小数点数（`f`）、ブロブ（`b`）タイプ
- **チャンネル範囲**: 1-512 DMXチャンネル

## サンプルスクリプト

テストと統合のためのサンプルスクリプトが `examples/osc/` ディレクトリにあります：

- **osc-receiver-example.js** - obakesanからDMXデータを受信してコンソールに出力
- **osc-transmitter-example.js** - obakesanにテストパターンを送信（両方の入力モードをサポート）

使用方法については [`examples/osc/README.md`](../../examples/osc/README.md) を参照してください。
